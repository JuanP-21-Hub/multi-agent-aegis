# 검증 기록

2026-11-17, GitHub Actions의 격리된 Ubuntu/Docker/PostgreSQL 환경에서 실행했다.
Windows 작업 환경에는 Docker 명령이 없고 WSL 조회가 거부되어 사용자의 실제 Docker Desktop과 기존 DB는 건드리지 않았다.

## 확인된 첫 실행

- 커밋: 72f7e1312936dc809ba28b3d3034358bcd7c8ef1
- 실행: https://github.com/JuanP-21-Hub/multi-agent-aegis/actions/runs/44076967794
- 결과: 성공
- 실제 PostgreSQL 17 기반 API 통합 테스트 11개 통과
- 프론트 공통 API/JWT 클라이언트 테스트 4개 통과
- Nginx → FastAPI → DB 회원가입/로그인/본인정보/계좌개설/PIN 검증 통과
- 기존 형식의 고객/계좌/거래/직원 데이터에 마이그레이션 2회 적용 및 보존 검사 통과
- DB/backend/web 컨테이너 재시작 후 고객·계좌 보존 검사 통과

## 검사 항목

| 항목 | 검증 방식 |
|---|---|
| 가입 → DB → 고객 로그인 → 본인 정보 | 실제 PG와 FastAPI TestClient 및 Nginx HTTP 요청 |
| 비밀번호 해시, RRN 암호화, 끝4자리 | DB 값 조회, Argon2 검증, Fernet 복호화 일치 검사 |
| 계좌 개설/번호/잔액/상태/목록/PIN | API 및 DB 해시 확인, 타인 PIN 접근 거부 |
| 직원 로그인/본인정보/고객목록/상세/계좌 | 실제 PG API 호출, 페이지 조회 및 끝4자리 검사 |
| 직원 생성/활성·비활성/기존 토큰 거부 | 비활성·재활성 모두 이전 토큰 401 확인 |
| 중복/비밀번호 오류/미인증/직원 권한 | 409/401/403 응답 검사 |
| 만료 토큰/잘못된 토큰/로그아웃 | JWT 및 토큰 버전 무효화 확인 |
| BOLA fixed/vulnerable | TestClient에서 소유권 검사 차이와 나머지 권한 유지 확인 |
| 감사로그/JSONL/민감값 제외 | 실제 저장 레코드, 다운로드 행 JSON 파싱, 원문 미포함 검사 |
| 422 오류의 민감값 제외 | 잘못된 RRN/비밀번호 요청 후 응답에 원문/input/ctx 없는지 검사 |
| 데이터 보존 | 마이그레이션 2회 + 재시작 이후 동일 고객/계좌 확인 |
| 프론트 인증 | Bearer 헤더, 새로고침 복원, 저장기한, 401/403, JSONL 인증의 Node 테스트 |

최종 Chromium 화면 조작 및 서버 환경변수로 모드를 재기동하는 검사는 추가 실행 결과를 아래에 기록한다.

## 실행하지 않은 환경 / 남은 한계

- 사용자의 Windows Docker Desktop + WSL2 Ubuntu 실기기, 실제 기존 볼륨/개인 데이터에는 적용하지 않았다.
- 기존 데이터 보존 검사는 원본 스키마로 만든 테스트 데이터에 대한 결과다. 사용자 DB 전체 검증을 뜻하지 않는다.
- 부하/장시간 운영/침투 테스트를 수행하지 않았다. TLS, 로그인·PIN 시도 횟수 제한, 로그 보관 정책은 별도 보완 대상이다.
- 일반 직원과 ADMIN은 기존 백엔드/팀원 구현의 범위에 맞춰 같은 직원 기능을 사용한다.
- 감사로그 저장 장애가 발생해도 이미 처리된 요청을 롤백하지 않으며 X-Audit-Persisted=false와 화면 알림으로 표시한다.
- 자동 토큰 갱신은 없고 최대 1시간 후 다시 로그인해야 한다. 로그인 유지 선택 시 JWT는 localStorage에 저장된다.
- 활동 로그 화면과 다운로드는 최근 200건이다. 전체 과거 기록은 before_id/limit로 페이지별 조회할 수 있다.
- Firefox/Safari 및 실제 모바일 단말은 검증하지 않았다.
