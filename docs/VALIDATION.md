별도로 서버를 LAB_MODE=fixed와 vulnerable로 각각 재생성하고 Nginx를 통해 실제 HTTP 요청을 보냈다.
다른 고객 조회는 fixed=403 / vulnerable=200, 미로그인=401 / 고객의 직원 목록 요청=403이었다.
다시 fixed로 복구한 후 DB/backend/web을 재시작하고 동일 고객/계좌 데이터가 유지되는 것을 확인했다.

실행 페이지의 browser-screenshots 아티팩트에는 고객 정보 화면과 직원 감사로그 화면 캡처가 있다.
캡처는 자동 생성한 테스트 데이터만 포함한다. 최종 코드 검증 후 변경은 이 결과 문서뿐이다.

## 코드 확인에 한정한 항목

- compose.existing.yaml의 외부 볼륨 연결 설정과 사용자 기기의 실제 볼륨 이름 선택.
- getpass 기반 최초 직원 생성 CLI의 대화형 입력. 직원 생성 API와 별도 브라우저 직원 생성은 실행 검증했다.
- 기존 사용자 데이터 전체의 유효성 및 실제 기존 .env의 암호화 키 일치 여부.
- 모든 반응형 화면의 시각적 품질. Chromium 데스크톱 기능 흐름과 캡처는 확인했으나 전 해상도 시각 비교는 하지 않았다.

## 실행하지 않은 환경 / 남은 한계

- 사용자의 Windows Docker Desktop + WSL2 Ubuntu 실기기, 실제 기존 볼륨/개인 데이터에는 적용하지 않았다.
- 기존 데이터 보존 검사는 원본 스키마로 만든 테스트 데이터에 대한 결과다. 사용자 DB 전체 검증을 뜻하지 않는다.
- 부하/장시간 운영/침투 테스트를 수행하지 않았다. TLS, 로그인·PIN 시도 횟수 제한, 로그 보관 정책은 별도 보완 대상이다.
- 일반 직원과 ADMIN은 기존 백엔드/팀원 구현의 범위에 맞춰 같은 직원 기능을 사용한다.
- 감사로그 저장 장애가 발생해도 이미 처리된 요청을 롤백하지 않으며 X-Audit-Persisted=false와 화면 알림으로 표시한다.
- 자동 토큰 갱신은 없고 최대 1시간 후 다시 로그인해야 한다. 로그인 유지 선택 시 JWT는 localStorage에 저장된다.
- 활동 로그 화면과 다운로드는 최근 200건이다. 전체 과거 기록은 before_id/limit로 페이지별 조회할 수 있다.
- Firefox/Safari 및 실제 모바일 단말은 검증하지 않았다.
